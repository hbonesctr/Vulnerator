## Vulnerator 2.0 — 7.0.0 beta 5

### Database engine check at startup
If Windows refuses to load the native SQLite library (`e_sqlite3.dll`), Vulnerator now says so when it starts, with the
reason and what to do, instead of failing quietly on every screen. In beta 4 this showed only in the log as
"Unable to load DLL 'e_sqlite3': Access is denied", and the STIG library, benchmarks and file ingestion could not load.

Usual causes:
- **The files still carry the "downloaded from the internet" mark.** Unblock the zip (Properties > Unblock) *before*
  extracting it, or run `Get-ChildItem -Recurse | Unblock-File` in PowerShell from the Vulnerator folder.
- **Endpoint security / application control** blocks or quarantined `e_sqlite3.dll`. Ask your administrator to allow
  it: its SHA-256 is below, and every file's hash is in the attached `file-hashes.txt`.
- **The file is missing:** extract the whole zip again.

### Release assets
Each release now lists the SHA-256 of `Vulnerator.exe` and `e_sqlite3.dll` and attaches the hash of every program file,
for allow-listing.

Everything else is as in beta 4.
