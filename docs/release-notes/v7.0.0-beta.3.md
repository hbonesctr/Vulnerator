## Vulnerator 2.0 — 7.0.0 beta 3

**Fixes the startup problem in beta 1 and beta 2: Vulnerator.exe exited immediately, with no window and no message.**

### Cause
The configuration file (inherited from upstream Vulnerator) redirected eight core .NET libraries (System.Runtime,
System.IO, System.Linq and others) to newer package versions that are not in the program folder. The first screen
component could not load, and Windows closed the program before Vulnerator's own error handling and log were running.
.NET Framework 4.8 provides these libraries itself; the redirects are removed.

### Now checked on every build
The build starts `Vulnerator.exe`, waits for its window, and on failure reports the crash from the Windows event log
and the library that failed to load.

### Everything else
Same as beta 2: System.Data.SQLite 2.0.4 with SQLite 3.53.4, NIST SP 800-53 Rev 5, eMASS exports, rebuilt imports
(CKL / CKLB, ACAS .nessus and CSV, SCAP / SCC XCCDF, STIG library), CKL export, offline by default. See the beta 1 and
beta 2 notes.

### First start
The first window asks where to keep the database: **Portable** (next to Vulnerator.exe; the folder must be writable) or
**Persistent** (a database file you choose). The first launch builds the reference data and can take up to a minute.
