## Vulnerator 2.0 — 7.4.0 beta 1

**Add-on support.** Vulnerator can now load optional add-ons, such as dashboards or integrations. No add-ons are
included; this release adds the mechanism only, and nothing changes if you don't use any.

### How it works
- Add-ons go in the new **Add-ons** folder next to Vulnerator.exe. The main file ends in `.AddOn.dll`; an add-on with
  several files can have its own folder there. Restart Vulnerator after adding one.
- An add-on can add pages to the menu (before News) and options under **Settings > Integrations**. That section also
  lists every add-on found and whether it loaded.
- Add-ons **read** findings and hardware through a read-only database connection. They cannot change the database.
- A broken, damaged or incompatible add-on is skipped and the reason goes in the log. Vulnerator still starts.
- Each add-on gets its own data folder next to the database, so a portable copy keeps it.
- Files that Windows marks as downloaded from the internet can't be loaded. Unblock them (right-click, **Properties**,
  **Unblock**) and restart. Settings > Integrations says so when this happens.
- Works with strong-name bypass turned off, without admin rights, and with no native DLLs.

### For add-on developers
- `Vulnerator.AddOns.dll` (MIT, with XML documentation) ships in the program folder and is the only file an add-on
  compiles against. It is versioned separately (interface version 1).

### Tests
- The build compiles throw-away test add-ons (none ship) and checks the following: a working add-on, one in its own
  folder with a dependency, and add-ons that must be skipped (fails while starting, needs a newer version, not an
  add-on, wrong entry type, damaged file, duplicate ID). It also checks the read-only data, the menu pages and the
  Settings section.
