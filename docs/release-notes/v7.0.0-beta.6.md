## Vulnerator 2.0 — 7.0.0 beta 6

**Fixes "Unable to load DLL 'e_sqlite3': Access is denied" on locked-down machines.** Vulnerator now uses the SQLite that
is part of Windows instead of shipping its own.

### What changed
- Endpoint protection on managed DoD workstations commonly refuses to load native DLLs from user-writable folders (your
  profile, Downloads, Desktop). Beta 2–5 shipped SQLite as `e_sqlite3.dll` next to `Vulnerator.exe`, so the database
  engine could not load there and nothing could be imported.
- Vulnerator now uses **`winsqlite3.dll` from `C:\Windows\System32`**, which is part of Windows, signed by Microsoft and
  kept current by Windows Update. **The program folder contains no native DLLs.**
- Vulnerator is now a **64-bit** program (64-bit Windows 10 / 11 or Server 2016 and later).

### Your database
Databases created by earlier betas open unchanged.

### Checking it
On start, if the database engine cannot load, Vulnerator says why. To test on a machine before use, run
`Test-RealData.ps1` from the program folder against a folder of your files (it runs in 64-bit PowerShell).

Everything else is as in beta 5.
